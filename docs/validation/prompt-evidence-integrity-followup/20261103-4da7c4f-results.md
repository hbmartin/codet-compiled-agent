## Reproductions and retained failures

The passing runtime regressions cover deferred cleanup/submission, original request ownership after expiry/replacement, injected output without native association, successful separation following deferral, allocation failure before pending ownership, failed-frame refresh suppression, bounded native reads, truncation, and safe helper PIDs. Native mutants prove the pending owner, separator, fixture printer, PID guard, refresh ordering, size bound, and allocation ordering assertions are effective.

Three earlier attempts remain under their original capture identities in the historical-attempt artifact and archived inputs. They cannot satisfy current acceptance:

1. `prompt-evidence-integrity-20261103-frozen`: Debug CTest failed; the subsequent ASan build was interrupted. Those failures exposed paging/fixture assumptions and duplicate tail presentation.
2. `prompt-evidence-integrity-20261103-run2`: Debug and ASan CTest failed the archive-inspection fixture; TSan build was interrupted. The fixture now uses an independent inspection operation budget after the provider callback, while retaining its default-budget and durable-content assertions.
3. `prompt-evidence-integrity-20261103-run3`: all non-benchmark required checks passed, but benchmarking stopped at baseline Git inspection. A nested archive had been used as the Git repository cwd; the corrected common harness passes repository and source paths separately. No partial campaign is presented as a complete benchmark result.

Historical published reports, CSV samples, exact-command manifests, and source blobs are unchanged. Hardened retained producer entry points write new explicit outputs; no historical exit statuses were reconstructed.

## Measurements

Identical separately declared harness/support files were compiled against each variant's verified library and headers, with matching Release compiler settings. The immutable baseline was never overlaid. One warm-up and five alternating measured runs per variant were performed in each of two sets, without concurrent analyzers: **600 samples total, 500 measured, 25 workloads**. Positive controls verified allocation, geometry, write, fstat, fcntl, pipe-bound, and Python allocation observations.

All reported non-time counters match between variants for the C++ line, diagnostic, and export workloads. Tooling counters differ, so the bundle explicitly reports `all_measured_work_equal: false`. Python metrics are retained allocations/bytes and peak traced memory, not cumulative allocation totals. Other native timing differences are mixed; no runtime speedup or timing threshold is claimed. No lock-consolidation experiment was revived.

## Platform and policy limits

Host: Darwin arm64, Apple Clang 21.0.0, Homebrew Clang-Tidy 23.1.3, Cppcheck 2.22.0. Existing Darwin warning accommodations in the baseline campaign are preserved identically in both variants. Network TLS opt-in and native Tiger desktop acceptance were explicitly skipped. The intentionally disabled fixture-printer assertion probe is exercised only through its isolated expected-failure control.

Docker, Podman, and the PPC compiler were unavailable. Ubuntu/container runtime, native PPC/Tiger builds, and native Tiger acceptance therefore remain unverified; host cross-selection is not a substitute. No previous CI run supplies coverage for these changes. The PR may obtain new CI after publication, but it is separate from this local campaign.

Blocking TTY output and irrecoverable emergency delivery remain best effort. Native inspection enforces the opening size, not a content snapshot. Unicode policies, raw submitted/data bytes, durable completion, cancellation precedence, replay order, terminal ownership, and storage formats remain unchanged. The two documented Sonar local-tool trust-boundary findings and GitHub threads are untouched.
